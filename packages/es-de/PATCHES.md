# es-de patches

The RPM builds the ES-DE commit in `SOURCE.env` with `patches/` on top. `%check` builds `escape-test.cpp` with the
patched `es-core/src/utils/FileSystemUtil.cpp` (`--gc-sections` drops the parts that need the rest of es-core) and
runs it, then builds `rocknix-test.cpp` with `es-app/src/RocknixGamelist.cpp`, `FileSystemUtil.cpp`, `TimeUtil.cpp`,
`Log.cpp` and pugixml and runs it against fixture trees in a temp dir.

`0002` to `0004` read a ROCKNIX card in place when `LegacyGamelistFileLocation` is on. Their logic is in
`es-app/src/RocknixGamelist.cpp` (added by `0002`, pugixml and `FileSystemUtil` only); ROCKNIX's media paths are kept
per entry in the `FileData::mRocknixMedia` member (`0004`).

| Patch | Origin | Why on MicroOS | Test |
|---|---|---|---|
| `0001-escape-every-shell-special-byte-in-unix-launch-paths.patch` | mine, written new; upstream `master` has no fix | ES-DE puts `getEscapedPath` output into the launch command it runs through `/bin/sh`, and 3.5.0 leaves backtick, `\|`, newline, tab, `#` and `~` unescaped and skips a character that follows a backslash, so a ROM name on the SD card could run a command. Every byte outside `[A-Za-z0-9/._-+,:@%]` below 0x80 gets a backslash, a newline goes in double quotes. The output stays backslash escaped, so the callers that strip backslashes to get the plain path (`%GAMEDIR%`, `%EMUPATH%`, desktop files, scripting events) keep working | `escape-test`: 18 names with backtick, `\|`, `$( )`, newline, tab, quotes, `&`, `;`, `>`, globs, `#`, `~`, `$HOME`, `!`, a backslash before `$( )` and UTF-8 round trip through `sh -c "printf '%s' <path>"` (against `getGenericPath`, which turns `\` into `/`) and none runs the canary script; on unpatched 3.5.0 the backtick, `\|` and newline names run it |
| `0002-gamelist-read-and-write-rocknix-gamelists-in-the-sys.patch` | mine, written new | ROCKNIX keeps `gamelist.xml` in each system folder. With legacy on, a system under `ROMDirectory` reads and writes only the system folder file (`gamelistPaths`), so an appdata gamelist from internal storage or another card never lands on the card; a system outside it (`microos`) keeps appdata. The card file is written to `gamelist.xml.tmp` (opened with `O_NOFOLLOW`, so a planted link is never followed), flushed with `fsync` and renamed over `gamelist.xml` (`saveGamelist`) | `rocknix-test`: read and write paths for legacy on and off with a system under `roms/`, `roms` itself, a `roms2/gba` sibling and a root outside; `saveGamelist` writes with no temp left; a temp path that cannot be opened (dangling symlink, a symlink to another file, or a directory) and a failed rename keep the old file and leave no temp of its own; the linked file stays as it was; the read only dir case runs only when not root, so not in rpmbuild |
| `0003-gamelist-keep-unknown-data-of-rewritten-entries.patch` | mine, written new | ES-DE rewrites a changed entry from its own keys, so the first launch (`playcount`, `lastplayed`) drops ROCKNIX's `id`, `<image>`, `<thumbnail>`, `<video>`, `<md5>` and `<scrap>`. The new node gets every attribute and unknown element of the old one (`keepUnknown`, in every mode) before the default name check, which now also keeps a node with attributes (`defaultNameOnly`). With legacy on, ROCKNIX's absolute `/storage/roms/<system>/` paths read as `./` (`normalizeRomPath`) | `rocknix-test`: a ROCKNIX node keeps `id`, media, `md5` and `<scrap name= date=>` with one `playcount`; a default name node with ROCKNIX tags or only an `id` is kept, a plain one is not; absolute, nested, relative, foreign and other system paths; ROCKNIX ES values for `releasedate`, `lastplayed` (ES-DE `TimeUtil` against `strptime` with ROCKNIX's format), `rating` (ES-DE's `stof` and rounding), `playcount` and `favorite` read by ES-DE's expressions and the values ES-DE writes back into a node read by ROCKNIX's |
| `0004-media-show-rocknix-gamelist-art-where-es-de-has-none.patch` | mine, written new | ROCKNIX scrapes into `<system>/images/` and points at the files from the gamelist; ES-DE only looks in its media directory. With legacy on, the parse stores the ROCKNIX tags per entry (`rocknixMedia`, `FileData::setRocknixMedia`). `FileData::getDisplayMediaPath` returns the ES-DE file for a type, else the ROCKNIX tag for it (`displayMedia`: image, screenshot and miximage `image`, cover `thumbnail`, marquee `marquee` then `wheel`, video, fanart, title screen `titleshot`, back cover `boxback`, manual) when the file, absolute `/storage/roms/<system>/` paths mapped as for `<path>`, resolves inside the system folder (`resolveTag`). Only the gamelist and system views, theme variant triggers, media viewer, PDF viewer and launch screen use it; the media viewer skips a file already listed. The scraper, media removal, miximage and orphaned data cleanup keep ES-DE's paths | `rocknix-test`: tags taken from a game and a folder node, empty ones skipped; relative and absolute ROCKNIX paths resolve; missing file, directory, `../`, absolute outside, another system's absolute path and an `images` symlink out give none; marquee falls back to `wheel` |
